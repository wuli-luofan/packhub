# 联机模组同步（房主下发 → 玩家自动下载 → 全部就绪后房主重启）

> 需求原文：**「多人联机，房主下载模组后，其他玩家自动下载，全部下载完成后，交给房主重启游戏」**

## 一、整体流程

```
房主                                    玩家 A / B / C
 │ 用 PackHub 装了模组（或点「把模组同步给玩家」）
 ├── 广播清单 MANIFEST ────────────────► 收到清单
 │                                       ├─ 允许接收？(设置项 allowServerModPush)
 │                                       ├─ 逐个小文件下载到自己的 mods/
 │  ◄──────── PROGRESS（第 n/N 个）──────┤   每个文件校验 sha1，已存在且一致则跳过
 │  ◄──────── READY（全部装好）──────────┤
 │  ◄──────── FAILED / DECLINE ─────────┤   失败或取消会如实回报
 │
 ├─ 所有玩家都 READY
 └─ 房主点「全部就绪，重启载入」（或开启 syncAutoRestart 自动）
        ├── 广播 RESTART ───────────────► 玩家跟着软重启，载入新模组
        └── 房主自己软重启
```

「交给房主重启」的含义：**重启时机由房主决定**。玩家只能下载，不能替房主重启；房主按下去之后，
所有已就绪的玩家会一起重启（否则他们的新模组也不会生效）。

## 二、界面

- 主界面底部 **「联机」** 按钮 → 联机同步界面。
- 房主视图：每个玩家一行，显示 `下载中 3/7`、`已就绪`、`失败: …`，附进度条；
  底部按钮：`把模组同步给玩家` / `全部就绪，重启载入` / `取消同步` / `打开 mods` / `返回`。
- 玩家视图：当前状态、房主下发的文件数、进度条；想中断就在「热加载/进度」界面取消，或直接拒绝接收。
- 房主装了新模组时**自动**广播一次（`enableHostModSync=true` 时）。

## 三、设置项（`config/packhub.json`，设置界面里可改）

| 键 | 默认 | 作用 |
| --- | --- | --- |
| `enableHostModSync` | `true` | 作为房主时，装了模组就自动把清单广播给其他玩家 |
| `allowServerModPush` | `true` | 作为玩家时，允许房主/服务器把模组推到本机自动下载 |
| `syncAutoRestart` | `false` | 全部玩家就绪后自动重启（默认关，交给房主点按钮） |
| `syncResourcePacks` | `false` | 同步时是否也带上资源包/光影 |
| `syncMaxFileSizeMb` | `200` | 单个文件超过这个大小就不下发，防止误推大整合包 |

## 四、安全与信任模型

房主会告诉你去下载某些 URL，这本质上是一种信任：

- 只能由**你当前连接的服务器**下发；玩家之间的消息不互相转发，房主只接受来自自己服务器连接的消息。
- 所有文件下载后都会**校验 sha1**（清单里带的哈希），对不上就丢弃，不会留下半截文件。
- 下载目录固定是 `.minecraft/mods/`（或对应类型目录），不会写到别处。
- 不接受就在设置里把 `allowServerModPush` 关掉，或者收到提示时直接取消。
- 单文件大小上限 + 条目数上限（512）防止内存与磁盘被塞爆。

## 五、已知边界

- **对面也要装 PackHub**。没有装的一方频道不存在，房主只是看不到这名玩家（不会报错、不会崩）。
- 普通 Fabric/NeoForge 模组**必须重启**才能生效，这就是为什么流程最后要房主重启；
  资源包/光影/数据包/插件型 jar 本来就能热加载，不需要重启。
- 单人/局域网房主（整合服务器）走的是同一条通道；专用服务器上本模组按 `client` 环境加载，
  不参与同步（要支持专用服务器需要在 `fabric.mod.json` / `neoforge.mods.toml` 里把环境放开）。
- 客户端取消同步后，已下载完的文件仍在 `mods/` 里（下次会按 sha1 直接跳过）；不会自动删除。

## 六、协议

`com.packhub.sync` 下与游戏无关的纯逻辑（可离线单测）：

- `SyncEntry` / `SyncManifest`：清单与条目，长度前缀二进制编码，协议版本号写在头 4 字节。
- `SyncMessage`：`HELLO / MANIFEST / ACCEPT / DECLINE / PROGRESS / READY / FAILED / RESTART / CANCEL`。
- `SyncDownloader`：按清单下载、跳过已存在且一致的文件、单个失败不影响其他、可随时取消。
- `SyncManager`：房主端汇总与重启决策、玩家端自动下载与回报（依赖 `NetworkBridge`）。

加载器网络由 `com.packhub.platform.NetworkBridge` 抽象，两个加载器各自实现：

- Fabric：`FabricNetwork`（Fabric API Payload 网络，`packhub:sync` 频道，数据以 Base64 字符串承载）。
- NeoForge：`NeoForgeNetwork`（原版 Payload + `PacketDistributor`）。

拿不到通道时返回 `NetworkBridge.NOOP`，界面上只显示「不可用」，不影响单机使用。
